# P1 开环标定步骤（照着做，把符号和死区量出来）

> 目标：把 `user/app_config.h` 第 9 节的 `MOTOR_SIGN_*` 和 `MOTOR_DEADBAND_*`
> 全部换成**实测值**。这一步不做完，任何 PID 参数都是瞎调。

---

## 0. 前置检查（不做完别上电）

| 检查项 | 怎么确认 |
|---|---|
| 调试串口接线 | USB-TTL 的 **RX → PG14**、**GND 与主板共地**（TX 从 PC6 挪到 PG14 了） |
| 串口参数 | 115200 8N1，能稳定看到 10 Hz 的两行打印 |
| 蓝牙链路 | 第一行打印末列先是 `LOST`，连上手柄后变 `ON`，推动摇杆数值跟随 |
| TB6612 的 STBY | 已外接 3V3（你说已做） |
| 电池 | 12 V，四个轮子**悬空或车架空**（标定阶段不要让车落地跑） |

上电后串口应出现（每秒 10 组，两行一组）：

```
LX=   0 LY=   0 RX=   0 RY=   0 BTN=0x000000 LT=  0 RT=  0 LOST
WHEEL mm/s FL=    0 FR=    0 RL=    0 RR=    0 | DUTY FL=    0 FR=    0 RL=    0 RR=    0
```

上电时 `DUTY` 全是 0 是**正确的**（`online == 0` 时速度环强制安全态）。

---

## 1. 确认轮子的物理位置（先做这一步）

`WheelId_e` 的映射是：

| 标识 | 物理位置 | PWM | 方向脚 | 编码器 |
|---|---|---|---|---|
| `WHEEL_FL` | 左前 | TIM9_CH1 / PE5 | PE1 / PE2 | TIM2 / PA0,PA1 |
| `WHEEL_FR` | 右前 | TIM9_CH2 / PE6 | PE3 / PE4 | TIM1 / PE9,PE11 |
| `WHEEL_RL` | 左后 | TIM8_CH3 / PC8 | PG3 / PG4 | TIM4 / PB6,PB7 |
| `WHEEL_RR` | 右后 | TIM8_CH4 / PC9 | PG5 / PG6 | TIM3 / PB4,PB5 |

**请核对这个表和你实车的接线是否一致。** 不一致的话先改 `app_types.h` 的注释，
并在心里（或纸上）把顺序对齐 —— 顺序错了后面所有标定都是错的。

---

## 2. 标定 `MOTOR_SIGN_PWM_*` 和 `MOTOR_SIGN_DIR_*`（轮子转的方向）

**目标**：让「打印里 `DUTY` 为正」== 「该轮物理上前进」。

步骤：

1. 把车架起来，四个轮子悬空。
2. 把 `ly` 缓慢推到底（**前进方向**）。
3. 观察四个轮子的实际转向，在纸上记下每个轮子：
   - 轮子朝车头方向转（前进）→ 该轮 **暂记 OK**
   - 轮子反向转（后退）→ 该轮 **需要取反**
4. 对需要取反的轮子，把 `MOTOR_SIGN_PWM_XX` 的 `1` 改成 `-1`。
5. 重新上电复测，直到四个轮子在 `ly` 正推时**全部朝前转**。

> `MOTOR_SIGN_DIR_*` 只有在 `MOTOR_SIGN_PWM_*` 取反后仍然不对、或者你怀疑
> AIN1/AIN2 接反时才需要动。正常情况**只改 `SIGN_PWM` 就够了**，因为它和
> `SIGN_DIR` 是等效的两个反相开关；两个都改等于没改。

---

## 3. 标定 `MOTOR_SIGN_ENC_*`（编码器读数方向）

**目标**：让「打印里 `WHEEL mm/s` 为正」== 「该轮物理上前进」。

步骤：

1. 仍然 `ly` 正推到底（此时四个轮子都在物理前进，第 2 步已保证）。
2. 看第二行打印的 `FL/FR/RL/RR` 四个速度值的**符号**：
   - 正值 → 该轮 **暂记 OK**
   - 负值 → 该轮 **需要取反**
3. 对需要取反的轮子，把 `MOTOR_SIGN_ENC_XX` 的 `1` 改成 `-1`。
4. 重新上电复测，直到 `ly` 正推时四个速度**全为正**。

> 这一步是「麦轮直行不跑偏」的前提：如果某一轮的速度符号反了，
> 速度环会把它当负反馈去纠，结果那一轮会**反向猛冲**。

---

## 4. 标定 `MOTOR_DEADBAND_*`（每个轮子的启动死区）

**目标**：量出每个轮子「刚开始转动」时的占空比计数，填进 `MOTOR_DEADBAND_XX`。

步骤：

1. 把 `ly` 推到大约 **1/3 行程**，让四个轮子都稳定转起来，记下 `DUTY` 的值。
2. **非常缓慢地**把 `ly` 往回收，同时盯着四个轮子的转速。
3. 记录**每个轮子最先停止转动**时那个轮子的 `DUTY` 值 —— 那就是它的近似死区。
   （因为标定模式下四个轮子吃同一个 `DUTY`，所以不同轮子停转的时刻不同，
   停得最早的那个死区最大。）
4. 为了提高精度，可以重复几次，取平均值。
5. 把这四个值填进 `MOTOR_DEADBAND_FL/FR/RL/RR`。

> 参考量级：本车电机扭矩很宽裕，死区预计在 **800 ~ 1500**（约 10%~18%）。
> 我给的初值 1000 只是估计，**必须实测替换**。
> 死区填大了会导致低速段一顿一顿，填小了会导致低速段给指令但不转（有稳态误差）。

---

## 5. 复核麦轮运动学符号（这一步定「直行/横移/自转」对不对）

标定完上面四项后，把 `MOTOR_TEST_MODE` 改成 **0**（闭环），或者先在标定模式下
用**机械方法**复核：给一个方向的占空比，看四个轮子的转向组合是否符合 X 型麦轮的预期。

闭环模式下的复核顺序（**一次只给一个分量**，这是关键）：

| 动作 | 摇杆 | 预期 |
|---|---|---|
| 前进 | `ly` 正推 | 四轮全朝前，车前进（不歪、不转） |
| 后退 | `ly` 负推 | 四轮全朝后 |
| 左移 | `lx` 负推 | 四轮转向组合让车**平移向左**（车头方向不变） |
| 右移 | `lx` 正推 | 平移向右 |
| 逆时针自转 | `rx` 负推 | 车原地逆时针转 |
| 顺时针自转 | `rx` 正推 | 车原地顺时针转 |

**如果前进时车斜着走** → 说明某个轮的 `vy` 项符号反了 →
检查那一轮的 `SIGN_PWM` / `SIGN_ENC`；
**如果自转时车平移** → 说明 `k·ω` 项的符号组合有轮子反了。

> 麦轮逆运动学的公式（`w_FL = vx+vy+kω` 等）本身是标准的，**符号问题一律靠
> `MOTOR_SIGN_*` 修，不要改公式**。

## 7. 进入闭环调参

1. 把 `MOTOR_TEST_MODE` 改为 `0`（改 `app_config.h`，或取消 `CMakeLists.txt`
   里 `MOTOR_TEST_MODE=0` 那行的注释）。
2. 按 `app_config.h` 第 10 节的顺序调：先只加 `Kp`（Ki=0），再加 `Ki`。
3. 调参时重点看第二行打印：`WHEEL mm/s` 是实测，`DUTY` 是输出。
   - 实测跟不上指令 → `Kp` 小
   - 实测在目标附近抖/啸叫 → `Kp` 大（或受 ±43 mm/s 量化噪声地板限制，见
     `app_config.h` 第 7 节）
   - 稳态有固定偏差 → 加 `Ki`

---

## 8. 安全提醒

- 标定阶段**一定把车架起来**，四轮悬空。
- 落地第一次测试时，先把 `MAX_VXY_MS` 临时改小（例如 `0.2f`），
  确认方向全对再恢复。
- 任何时候拔掉蓝牙，车必须在 600 ms 内停住；如果没停，先查
  `VelCtl_Feed()` 里的 `online` 检查，不要继续调 PID。
